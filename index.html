Question 1: Production War Story

Eliminating Cross-Cloud Coupling & Resolving vCD Token Timeouts

How a 30-minute API timeout in staging triggered an architectural refactoring to decouple failure domains

1. The Anti-Pattern & Mid-Apply Crash

  • Monolithic Root Module: Initially, cross-cloud networking was managed from a single root module using multiple provider aliases (aws, azurerm, vcd).
  • 30-Min Token Expiration: During a normal staging apply, Multinet VMware vCD session token expired at minute 30.
  • Crash Log: Error: [VCD-API] 401 Unauthorized: Session token has expired or is invalid on module.multinet.vcd_vapp_vm.worker[0].
  • Blast Radius Spillage: Pipeline aborted mid-flight; left orphaned AWS ALB target groups and orphaned DynamoDB locks.

2. Immediate 45-Min Incident Triage

  • Manual Lock Release: CLI intervention: ran terraform force-unlock <LOCK-ID> to release the unmanaged lock.
  • Target Group Cleanup: Manually audited and pruned dangling AWS ALB target groups to prevent routing traffic to dead instances.
  • Provider Keepalive: Reconfigured vCD provider session keepalive to 120 minutes to prevent mid-operation token drops.
  • Automated Retries: Wrapped API token generation in CI with pre-flight health validation.

3. Permanent Decoupled Architecture

  • Root Module Isolation: Permanently split infrastructure into completely independent root modules per cloud provider.
  • terraform_remote_state: Cross-cloud wiring connects exclusively through read-only remote state data sources and Vault.
  • Zero Cross-Cloud Blast Radius: Multinet ISP API downtime can never block or corrupt AWS or Azure infrastructure pipelines.
  • Isolated CI/CD: GitHub Actions runs independent plan/apply jobs with isolated state locks.
TALKING POINTS FOR CTO & VP ENG: • A key sign of a senior platform engineer is learning from architectural anti-patterns. • In early development, like many teams, cross-cloud networking was attempted using multiple provider blocks in a single root module. • In staging, vCD's 30-minute API token expired mid-apply. Because Terraform runs sequentially through dependencies, the failure in Multinet killed the entire run, leaving AWS ALBs orphaned and DynamoDB locked. • Rather than just patching the timeout to 120 minutes, I spearheaded the architectural refactoring to decouple the environments completely. • By enforcing `terraform_remote_state` and independent CI pipelines, failure domains are strictly isolated: no single cloud provider's API issues can ever block deployment to our other three clouds.

Question 8: Production War Story

The Failed DR Drill: Database Role Drift & Client DNS Caching

How a 100% error spike during a scheduled quarterly drill revealed hidden pglogical DDL limits and enterprise DNS caching

1. The 60-Second Post-Cutover Disaster

  • Scheduled Drill: Simulated total AWS UAE outage during scheduled quarterly disaster exercise.
  • 100% Error Spike: Automated failover triggered cleanly, but 60 seconds after DNS cutover, Azure application errors jumped to 100%!
  • AKS Pod Error Log: 
    psycopg2.OperationalError:
FATAL: role "ahya_calc_worker" does not exist in database
  • Client DNS Failure: Partner enterprise banks cached dead AWS IP addresses, ignoring Cloudflare's 30s TTL.

2. Root Cause Analysis

  • pglogical DDL Blindspot: PostgreSQL logical replication synchronizes table DML, but does NOT replicate cluster-level roles, users, or grants.
  • Unmanaged ClickOps Drift: A newly released Scope 3 calculation worker had been deployed two weeks prior with a manually created DB user (ahya_calc_worker) on AWS Aurora.
  • Azure Auth Barrier: When AKS scaled up pods on Azure, they could not connect to Azure PostgreSQL because the user only existed on AWS.
  • Stale Enterprise Resolvers: Upstream corporate bank DNS resolvers ignored TTL expirations.

3. Engineering Resolution & Hardening

  • Emergency 8-Min Fix: Injected missing role and privileges across Azure Flexible Server via emergency Ansible playbook.
  • SchemaCrawler Drift Audits: Implemented daily automated CI pipeline diffing database roles, users, and schemas between AWS and Azure.
  • Cloudflare HTTP 307 Redirects: Configured Cloudflare Edge origin redirect rules returning HTTP 307 Temporary Redirects during DR events to bypass stubborn client DNS caches.
  • Subsequent Drills: Passed next quarterly exercise with zero errors and an RTO of 8 minutes 40 seconds.
TALKING POINTS FOR CTO & VP ENG: • Real leadership is demonstrating how you handle failure when an architecture breaks under testing. • During a quarterly DR simulation, 60 seconds after cutover, Azure AKS error rates spiked to 100%. Pods threw `role ahya_calc_worker does not exist`. • We uncovered a critical technical reality: PostgreSQL `pglogical` replicates table rows, but it does NOT replicate cluster roles or users! An engineer had created that user manually on AWS two weeks earlier. • Furthermore, client bank ERPs had stubborn DNS resolvers that cached the dead AWS IP despite our 30-second TTL. • We recovered in 8 minutes with an emergency Ansible script. Then we engineered permanent systemic safeguards: daily SchemaCrawler DDL drift checks in CI, and Cloudflare HTTP 307 temporary redirect rules to bypass broken client DNS resolvers.
